Directive-aware microgrid scheduling

Turn operator notes into a 24-hour battery plan — deterministically.

Free-text directives (window constraints, reserve floors, grid caps) are interpreted into a typed structure and solved as a linear program. Hard physics constraints are satisfied by construction; no rollout policy, no heuristics that can drift.

How it works

  1. 1 Operator note — free text, 1–3 entries per schedule.
  2. 2 Directive parser — maps the note into a typed directive (window, reserve, cap, etc.).
  3. 3 LP scheduler — minimizes grid cost subject to battery, solar, and directive constraints.
  4. 4 Validator — replays every constraint before the plan is returned.

Backend

        

          FastAPI on Python 3.14. Linear program formulated in PuLP and solved by the bundled CBC solver
          — typically solves in single-digit milliseconds for a 24-hour horizon.
        

      

      

        
Parsing

        

          Operator notes are classified into one of six directive types with hour ranges. A small
          instruction-tuned LLM provides the parser; a deterministic rules fallback is used when the
          LLM is unavailable or returns unparseable output.
        

      

      

        
Validation

        

          Every returned plan is replayed through 11+ constraint checks — energy balance, battery
          bounds, charge/discharge rates, directive windows, end-of-day neutrality — before it leaves
          the service.
